# 나의 연금 현황 — 기술 사양

`/pension/my` 통합 대시보드의 데이터 흐름과 계산 규칙.

---

## 파일 구조

```
app/pension/my/
├── page.tsx      클라이언트 컴포넌트 (UI + 도움말)
└── actions.ts    getPensionOverview() — 세 연금 합산
```

계산은 직접 하지 않고 **각 화면과 같은 모듈을 재사용**한다.
값이 화면마다 어긋나면 안 되기 때문이다.

| 대상 | 재사용 모듈 |
|------|-------------|
| 퇴직연금 | `lib/pension-ret-calc.ts` — `buildRetirementRows`·`grownValue`. 급여 기준은 `retSettingsFromEnv()` (`PENSION_RET_*`) |
| 개인연금 | `lib/pension-per-calc.ts` `simulatePer()` |
| 프로필 | `lib/profile.ts` `ageOn` / `ageInYm` / `ymAtAge` / `retireEndYm` |
| 적립 계획 | `lib/settings.ts` `perSettingsFromEnv()` |

액션은 두 개다.

| 액션 | 내용 |
|------|------|
| `getPensionOverview()` | 요약 + 수령 시점별 (미래) + 참고 시나리오 2종 |
| `getPensionHistory()` | 월별 과거 실적 추이 |

참고 시나리오는 DB 조회가 없는 순수 계산이라 별도 액션으로 나누지 않고
`getPensionOverview()` 의 `withdraw`(퇴직금 중도인출) · `early`(국민연금 조기수령)
필드로 같이 내려보낸다. 환경 변수가 비어 있으면 각각 `null` 이고 카드가 렌더링되지 않는다.

## `getPensionOverview()` (`app/pension/my/actions.ts`)

`requireAdmin()` 으로 보호. 반환 타입:

```typescript
type PensionOverview = {
  today: string           // 'YYYY-MM'
  currentAge: number
  birthDate: string
  retireDate: string
  pensions: PensionSummary[]   // per / ret / nat 순
  stages: PayoutStage[]        // 수령 개시 시점별 합산
  peakMonthly: number          // 전부 받을 때의 월 합계
  ccAnnualRate: number         // 커버드콜 연 분배율 (공통 전제)
}
```

### 상수

```typescript
const NAT_PAYOUT_AGE   = 65        // 1969년 이후 출생자
const NAT_START_YM     = "2007-11" // 국민연금 가입 시작
const NAT_TOTAL_MONTHS = 319       // 총 납부 예정 개월
```

### 연금별 산출

| 연금 | 월 수령액 | 적립 현황 | 진행률 |
|------|-----------|-----------|--------|
| 국민연금 | `np_snapshots` 최신 `monthly_net` | 최신 `total_premium` | 납부 개월 / 319 |
| 퇴직연금 | 정년 행 `netMan` → `grownValue()` → × 연분배율 ÷ 12 | `calcCurrentSeverance()` 실수령 | 근속일수 / 입사~정년 |
| 개인연금 | `simulatePer().monthlyPayout` | 현재 보유수량 × 주가 | 현재 평가액 / 수령 시점 평가액 |

- 퇴직연금은 **만원 단위**로 계산되므로 마지막에 `× 10_000` 한다
- 개인연금 진행률은 개월이 아니라 **금액 기준**이다 (적립 시작 시점을 모르기 때문)
- 국민연금 스냅샷이 없으면 0원으로 표시된다 (에러를 내지 않는다)

### `stages` 생성

수령 개시 `startYm` 을 모아 중복 제거·정렬하고, 각 시점에서 **그때까지 시작된 연금을 합산**한다.

```typescript
const marks = [...new Set(pensions.map(p => p.startYm))].sort()
stages = marks.map(ym => {
  const active = pensions.filter(p => p.startYm <= ym)
  return { fromYm: ym, total: active.reduce(...), starting: /* 그 시점에 새로 시작 */ }
})
```

현재 데이터에서는 2단계가 나온다.

| 구간 | 나이 | 개인연금 | 퇴직연금 | 국민연금 | 합계 |
|------|------|----------|----------|----------|------|
| 2037.06~ | 63세 | 580만원 | 421만원 | — | **1,001만원** |
| 2039.06~ | 65세 | 580만원 | 421만원 | 132만원 | **1,133만원** |

**나이는 `ageInYm()` 으로 잰다.** 개시월은 생일이 든 달이라, 그 달 1일 기준으로 재면
생일 전이어서 한 살 적게 나온다 — 생일이 6/4 인데 `2039-06-01` 로 재면 만 64세다.
`ymAtAge(생년월일, 65) = 2039-06` 이므로 그 달에 도달하는 나이인 **65세**가 맞다.

같은 이유로 `currentAge` 도 그 달 1일이 아니라 **오늘 날짜**로 잰다(`toIsoDate(now)`).
생일이 든 달에만 어긋나서 눈에 잘 띄지 않는다.

## `getPensionHistory()` — 월별 과거 실적 추이

새 테이블을 만들지 않고 기존 데이터로 재구성한다.
`getPensionOverview()` 와 **분리된 액션**이다 — 화면 첫 페인트를 막지 않으려고 따로 부른다.

```typescript
type HistoryKind = PensionKind | "all"     // 합계 탭이 하나 더 있다
type HistoryRow = {
  ym: string
  base: number | null        // 개인=보유수량(주), 국민=총 납부액(원), 퇴직=없음
  monthly: number            // 월 수령액 — 세 연금 공통 축
  diff: number | null        // 직전 시점 대비 monthly 증감
  diffPct: number | null
  parts?: { per: number; ret: number; nat: number; natEstimated: boolean }  // 합계 탭 전용
}
type PensionHistory = {
  kind: HistoryKind
  baseLabel: string | null   // null 이면 그 컬럼을 그리지 않는다
  monthlyLabel: string       // '월 수령액 예상' / '월 분배금' / '월 수령 예상 (세후)'
  basisNote: string          // 어떤 전제로 나온 값인지
  rows: HistoryRow[]
  changePct: number | null   // 첫 행 대비 마지막 행
  rangeLabel: string         // '2026.05 → 2026.08' / '최근 12개월' / '확인 4회 · …'
}
```

**증감은 언제나 `monthly` 기준이다.** 연금마다 부가 지표(`base`)가 달라서,
그걸 기준으로 잡으면 세 탭의 `증가`·`증가율` 컬럼이 서로 다른 뜻이 된다.

### 연금마다 촘촘함이 다르다 — 억지로 맞추지 않는다

| 연금 | `base` | `monthly` 산출 | 범위 |
|------|--------|----------------|------|
| 개인연금 | 보유 수량 | 그 달의 수량·종가·분배율로 `simulatePer()` 재실행 (`startYm` = 그 달) | 보유가 생긴 달부터 |
| 퇴직연금 | 연 분배율 | 정년 퇴직금(고정) → `grownValue()` → 그 달의 분배율 — **DB 조회는 분배 이력뿐** | 최근 `RET_HISTORY_MONTHS`(12)개월 |
| 국민연금 | 총 납부액 | `np_snapshots.monthly_net` 그대로 | 확인 시점 4건 |

### 원칙 — "그 달에 이 화면을 봤다면 나왔을 값"

세 탭 모두 이 기준 하나로 통일한다. 그래서 **각 탭의 최신 행은 아래 연금별 카드와 정확히 일치**하고,
합계 탭의 최신 행은 상단 헤드라인 합계와 일치한다. 어긋나면 어느 한쪽이 잘못된 것이다.

| | 개인 | 퇴직 | 국민 | 합계 |
|---|---|---|---|---|
| 카드 | 5,803,386 | 4,210,000 | 1,320,920 | 11,334,306 |
| 표 최신행 | 5,803,386 | 4,210,000 | 1,320,920 | 11,334,306 |

**분배율도 그 달 시점 값으로 되살린다.** 요약 카드가 "최근 12회 평균"을 쓰므로,
과거 달도 `ref_date <= 그 달 말일` 인 최근 12회 평균(`monthlyRateAt()`)을 쓴다.

퇴직연금은 이 값 하나만 변한다 — 정년 퇴직금(17,722만)도 거치 개월(36)도 그 달 시점과 무관하다.
그래서 퇴직연금 탭의 `증가율`은 곧 **분배율이 움직인 만큼**이고, `base` 컬럼에 그 분배율을 같이 보여준다.

> 2026-01 의 −5.3% 는 실적 악화가 아니라 **2025-01 첫 분배(2.05%, 이례적으로 높음)가
> 12회 창에서 빠진 것**이다. 창이 짧아 초기 구간은 이런 흔들림이 있다.

```sql
-- 개인연금: 월별 마지막 거래일의 누적 순수량과 그날 종가
WITH months AS (
  SELECT TO_CHAR(e_date,'YYYY-MM') AS ym, MAX(e_date) AS eom
  FROM t_stock_amt WHERE stock_code = $2 GROUP BY 1
)
SELECT m.ym, a.e_amt::float8 AS price,
       (SELECT COALESCE(SUM(s.qty),0) FROM my_stock s
        WHERE s.account_no=$1 AND s.stock_code=$2
          AND TO_DATE(s.s_date,'YYYYMMDD') <= m.eom)::float8 AS quantity
FROM months m JOIN t_stock_amt a ON a.stock_code=$2 AND a.e_date=m.eom
ORDER BY m.ym
```

- 보유수량이 0인 달은 버린다 — 앞에 0 구간이 길게 붙으면 추이가 안 보인다
- **국민연금은 월 단위가 아니다.** 스냅샷 사이를 보간하지 않는다 —
  없는 데이터를 지어내는 셈이기 때문이다. `확인 4회` 로 표기한다
- 퇴직연금 이번 달 행은 월말이 아니라 **오늘까지**의 근속으로 계산한다

### 합계 탭 — 세 연금이 **모두** 값을 갖는 달만

이 화면의 목적이 "내 예상 연금액이 어떻게 변해왔나"라서, 합계가 실제 변화를 보여야 한다.
한 연금이 중간에 끼어들면 그 달에 합계가 껑충 뛰어 **추세가 아니라 착시**가 된다.
그래서 교집합만 담는다 — 지금은 개인연금이 가장 짧아(2026.05~) 그 범위가 곧 합계 범위다.
데이터가 쌓이면 자동으로 길어진다.

**국민연금만 보간한다.** 공단 확인이 1~2년에 한 번이라 보간하지 않으면 합계가 아예 성립하지 않는다.

| 구간 | 처리 |
|------|------|
| 확인 시점 사이 | **직선 보간** — 표에 `*` 로 추정치임을 표시 |
| 마지막 확인 이후 | 마지막 값 유지 — 없는 상승을 지어내지 않는다 |
| 첫 확인 이전 | 값 없음 → 그 달은 합계에서 제외 |

국민연금 단독 탭은 여전히 **보간하지 않는다.** 거기서는 확인 시점 자체가 정보다.

### 근속 기반 퇴직금 추이는 쓰지 않기로 했다

한때 퇴직연금 추이를 `calcCurrentSeverance()`(그 달에 퇴직 → 만 55세 매입 → 96개월 거치)로
냈었다. 근속이 쌓이는 만큼 우상향해 추이로는 보기 좋았지만, **아래 퇴직연금 카드와
값이 달라** 같은 화면에서 두 숫자가 충돌했다.

원인은 두 요인이 반대로 움직여 상쇄되지 않았기 때문이다 (현재 평균임금 789만원 기준).

```
원금  8,815만 / 17,722만 = 0.50배   ← 그 달 퇴직이 불리
거치  ×3.90  / ×1.67     = 2.34배   ← 그 달 퇴직이 유리 (55세 매입 → 8년 거치)
                           ─────
                           1.17배   → 카드보다 높게 나온다
```

지금은 **정년 기준 하나로 통일**했다. 화면 안에서 같은 이름의 값이 다른 뜻을 갖지 않는 게
우상향 그래프보다 중요하다.

실측(2026-08-29 기준):

| 연금 | 범위 | 월 수령액 변화 |
|------|------|----------------|
| **합계** | 2026.05 → 2026.08 | 1,230만 → 1,133만 **−7.8%** |
| 개인연금 | 2026.05 → 2026.08 | 679만 → 580만 **−14.5%** (2026-07 주가 26,320→20,300) |
| 퇴직연금 | 최근 12개월 | 454만 → 421만 **−7.3%** (분배율 17.99% → 17.13%) |
| 국민연금 | 2023.05 → 2026.08 | 111만 → 132만 **+19.3%** |

합계 탭 실측:

```
월        개인        퇴직        국민         합계        증가        증가율
2026-05  6,788,237  4,200,000  1,311,130   12,299,367  -           -
2026-06  6,910,083  4,210,000  1,314,393*  12,434,476  +135,109    +1.1%
2026-07  5,827,969  4,250,000  1,317,657*  11,395,626  -1,038,850  -8.4%
2026-08  5,803,386  4,210,000  1,320,920   11,334,306  -61,320     -0.5%
```

## 중도인출 참고 시나리오 (`calcWithdrawScenario()`)

`2029.06.05` 에 퇴직금을 중도인출하고 **계속 재직**하는 가정. 기존 계산을 대체하지 않고
하단에 참고 카드로만 붙인다. 계산은 [lib/pension-ret-calc.ts](../../../lib/pension-ret-calc.ts) 에 있다.

기준일은 `PENSION_RET_WITHDRAW_DATE` 환경 변수다. **비우면 카드가 통째로 사라진다** —
제도상 불가능하다고 판명되면 코드를 고치지 않고 값만 지우면 된다.

### 퇴직금을 두 번 받는 구조

중도인출로 끝이 아니다. 인출 후에도 다니므로 정년에 퇴직금이 **새로 발생**한다.
두 몫은 매입 시점이 달라 굴러가는 기간이 다르고, 세금도 각각 매겨진다.

| 몫 | 기간 | 근속 | 평균임금 | 세전 | 세금 | 실수령 | 매입 | 거치 | 월 분배금 |
|----|------|------|----------|------|------|--------|------|------|-----------|
| 중도인출분 | 2015.02~2029.06 | 14.29년 (세금 15년) | 849만 | 12,133만 | 385만 | 11,748만 | 2029.06 | 96개월 | **654만원** |
| 정년 추가분 | 2029.06~2034.06 | 5.07년 (세금 6년) | 949만 | 4,813만 | 181만 | 4,632만 | 2034.06 | 36개월 | **110만원** |

**`정년 추가분`은 남은 잔액이 아니다.** 중간정산을 하면 퇴직금 기산일이 정산 시점으로
리셋되므로, 인출일부터 정년까지의 근속만 새로 계산한 값이다. 이름을 `잔여분`으로 쓰면
잔액처럼 읽혀서 안 된다.

### 총액은 줄고 수령액은 는다 — 둘 다 보여준다

| | 기준 (정년 일시 수령) | 시나리오 |
|---|---|---|
| 63세 월 수령액 | 421만원 | **764만원** (+81%) |
| 3연금 합계 | 11,334,306원 | **14,764,306원** |
| 퇴직금 실수령 합 | 17,722만 | 16,380만 (**−1,342만**) |
| 퇴직소득세 합 | 652만 | 566만 (−86만) |

- 총액이 주는 이유 — 인출분을 **2029년 평균임금(849만)** 으로 정산한다.
  정년까지 한 번에 가면 전체 근속에 949만원이 적용된다
- 그런데도 수령액이 느는 이유 — 거치가 36개월(×1.66) → 96개월(×3.88)로 늘어
  복리가 그 손해를 압도한다
- 세금은 두 몫으로 쪼개지며 누진이 완화돼 오히려 준다

이 역설을 감추면 안 된다. 카드 하단에 총액 감소를 명시한다.

### ⚠️ 성립하지 않을 수 있다

**DB형 퇴직연금은 중도인출 규정 자체가 없다.** 근로자퇴직급여보장법의 중도인출은
DC형·IRP 대상이고, 법정 퇴직금의 중간정산도 무주택자 주택구입·전세보증금·6개월 이상
요양·파산·개인회생·천재지변 등 법정 사유에 한한다.

또 이 시나리오는 분배율 가정에 **8년을 더** 기대게 만든다. 도움말 `⚠️` 탭에 적어 두었다.

## 국민연금 조기수령 참고 시나리오 (`calcEarlyPension()`)

노령연금을 최대 5년 앞당겨 받고(조기노령연금) 그 돈을 커버드콜에 적립하는 가정.
계산은 [lib/pension-nat-calc.ts](../../../lib/pension-nat-calc.ts) 에 있다.

`PENSION_NAT_EARLY_YEARS` 를 비우면 카드가 통째로 사라진다.
`PENSION_NAT_INVEST_UNTIL_AGE` 는 적립을 끝내고 연금을 생활비로 돌리는 나이다(기본 65).

### 감액은 평생이다

```
감액률 = 앞당긴 연수 × 6%          (법정, 월 0.5%)
5년 → 30%  →  1,320,920원 → 924,644원
```

**나중에 원래 금액으로 돌아오지 않는다.** 이 점을 도움말에 명시했다.

### 적립식 재투자 — `accumulatedValue()`

퇴직연금의 `grownValue()`(일시금)와 달리 매월 같은 금액이 들어온다.

```
평가액 = 월 적립액 × ((1 + 월분배율)^개월 − 1) ÷ 월분배율
```

| 항목 | 값 |
|------|-----|
| 적립 | 만 60세(2034.06) ~ 65세(2039.06), 60개월 |
| 납입 | 924,644 × 60 = 5,548만원 |
| 평가액 | **8,684만원** (1.57배) |
| 월 분배금 | **1,239,658원** |

### 결과 — 감액분보다 분배금이 크다

| | 기준 (65세 정상 개시) | 시나리오 |
|---|---|---|
| 국민연금 월 수령액 | 1,320,920원 | **2,164,302원** (+64%) |
| 3연금 합계(65세~) | 11,334,306원 | **12,177,688원** |

- 잃는 것 — 매월 396,276원 감액 (평생)
- 얻는 것 — 매월 1,239,658원 분배금 + 5년 일찍 받은 5,548만원

### ⚠️ 이 표가 감추고 있는 것

- **만 60~63세는 세 연금 모두 수입이 0이다.** 정년 이후 개인·퇴직연금 개시 전인데
  국민연금마저 적립에 들어간다. 그 기간 생활비가 따로 있어야 성립한다
- **물가 연동을 잃는 게 진짜 비용이다.** 국민연금은 매년 오르지만 깎인 30%는 그 인상분에도
  그대로 적용되고, ETF 분배금은 물가 연동이 없다. 이 비교는 물가를 반영하지 않았으므로
  **오래 살수록 조기수령이 불리해진다**
- 조기노령연금은 일정 수준 이상의 사업·근로소득이 있으면 수급이 정지된다

## 화면 (`page.tsx`)

### 라이트 테마 유지

디자인 시안은 다크였으나 **레이아웃·구성만 가져오고 색은 라이트로 유지**한다
([main_design.md](../../main_design.md) 다크모드 미지원 규칙).

```
CARD = "bg-white border border-gray-200 rounded-2xl"
```

- 화면 하단 공백을 줄이려고 컨테이너에 `-mb-4 md:-mb-6` 를 걸어
  `AppLayout` 의 `main` 하단 패딩을 상쇄한다
- 구분선은 `border-gray-100`, 보조 면은 `bg-gray-50`
- **요약과 수령 시점별은 한 카드**다. 같은 이야기(합계 → 시점별 분해)라 나눌 이유가 없다.
  하단 구역만 `bg-gray-50/60` + `border-t` 로 구분하고, 스택 바 트랙은 `bg-gray-200/70` 을 쓴다

### 색상

연금별로 고정한다. 스택 바·카드·범례·아이콘이 같은 색을 쓴다.

| 연금 | 색 | 텍스트 | 카드 배경 |
|------|-----|--------|-----------|
| 개인연금 | purple | `text-purple-700` | `bg-purple-50` + `border-purple-200` |
| 퇴직연금 | emerald | `text-emerald-700` | `bg-emerald-50` + `border-emerald-200` |
| 국민연금 | blue | `text-blue-700` | `bg-blue-50` + `border-blue-200` |

아이콘은 `w-11~12` 원형에 `bg-gradient-to-br` + `ring-4 ring-{color}-100` 을 준다.
`PensionIcon` 이 연금별 SVG(사람 / 서류가방 / 은행)를 그린다.

### 숫자 표기

`splitKRW()` 로 숫자와 단위를 나눠 **단위만 작게** 쓴다 (`578` + `만원`).
합산 금액만 원 단위로 풀어 자릿수를 드러낸다 (`11,061,053원 / 월`).

### 같은 숫자를 두 번 쓰지 않는다

상단 카드에 연금별 **월 수령액**을 크게 쓰던 구역이 있었는데,
아래 스택 바(막대 안 금액)·연금별 카드(`5,779,923원`)와 **삼중 중복**이었다.
그 자리를 과거 추이로 바꿨다.

| 무엇 | 어디에서 |
|------|----------|
| 미래 월 수령액 (금액) | 스택 바 + 연금별 카드 |
| 비중(%) | 스택 바 **범례** (`● 개인연금 52%`) |
| 적립 현황 (금액) | 연금별 카드 |
| 과거 추이 | **상단 카드 — 표** |

상단 추이 표의 금액은 **과거 시점의 값**이라 카드의 현재값과 중복이 아니다.

### 과거 추이 표 (`HistoryTable`)

처음에는 스파크라인이었으나 **점이 3~4개짜리는 선으로 읽히지 않아** 표로 바꿨다.

- 연금마다 컬럼이 다르므로 **탭으로 나눈다** (`tab` 상태 + `active`). 기본 탭은 **합계**
  ```
  3연금 합계  월 | 개인연금 | 퇴직연금 | 국민연금 | 합계 | 증가 | 증가율
  개인연금    월 | 보유 수량 | 월 수령액 예상   | 증가 | 증가율
  퇴직연금    월 | 연 분배율 | 월 분배금        | 증가 | 증가율
  국민연금    월 | 총 납부액 | 월 수령 예상(세후) | 증가 | 증가율
  ```
- `baseLabel` 이 `null`(합계)이면 그 컬럼 자체를 그리지 않고,
  `kind === "all"` 일 때만 `parts` 로 연금별 3열을 편다
- `base` 표기는 `baseUnit` 이 정한다 — `shares`(1,891주) / `pct`(17.13%) / `won`(1.4억원)
- **최신 달이 위로** 오게 `[...rows].reverse()`
- 행 수가 연금마다 다르므로(4 / 4 / 12 / 4) `max-h-[188px] overflow-y-auto` 로 카드 높이를 고정한다.
  헤더는 `sticky top-0`
- 탭 줄 오른쪽에 `rangeLabel` + 전체 변화율, 표 위에 `basisNote` 를 둔다.
  `basisNote` 는 그 탭의 값이 어떤 전제로 나왔는지 밝히는 유일한 자리다
- 금액은 `fmt()` 로 원 단위 그대로 쓴다. `증가` 가 만원 단위로 반올림되면
  월 3만원짜리 변화가 통째로 사라진다

### 스택 바 (`StageBar`)

- 막대 전체 폭 = `stage.total / maxTotal` — 국민연금이 더해지면 막대가 길어진다
- 내부 분할 = 연금별 비중. 비중 12% 미만이면 라벨을 숨긴다
- 값이 0인 연금은 렌더링하지 않는다

### 도움말

공용 [components/HelpModal.tsx](../../../components/HelpModal.tsx), `variant="page"`.
탭은 `무엇을 모았나` / `공통 전제` / `⚠️ 한계` 3개.

- 연금별 성격 차이(실적 vs 예상)를 명확히 구분해 설명한다
- 커버드콜 비중을 계산해 보여준다 — 합계가 분배율 가정에 얼마나 기대는지
- 분배율·합계처럼 **조회 시점에 따라 달라지는 값은 본문에 그대로 넣는다**

## 알려진 제약 사항

- 국민연금 가입 시작·총 납부 개월이 상수다 (`NAT_START_YM`, `NAT_TOTAL_MONTHS`)
- 국민연금 개시 나이 65세도 상수다 — 조기·연기 수령 시나리오가 없다
- 정년~63세 공백 기간을 다루지 않는다
- 물가·건강보험료·세금 미반영
- 퇴직·개인연금이 같은 분배율 가정을 공유하므로, 분배율이 틀리면 **두 연금이 동시에** 틀린다
