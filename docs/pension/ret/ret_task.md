## 근속 진행 현황

### 날짜 계산

입사일·정년은 **공통 프로필 환경 변수**(`PROFILE_*`, `config/.env`)에서 읽는다 (개인연금 화면과 공유).
`getProfile()` 이 실패했을 때만 `FALLBACK_JOIN` / `FALLBACK_RETIRE` 상수를 쓴다.

```typescript
const profile = await getProfile()          // app/actions/profile.ts
const JOIN_DATE   = toDate(profile.join_date)    // 2015-02-23
const retireDate  = toDate(profile.retire_date)  // retire_rule 로 계산된 정년일

const progress = monthDiff(JOIN_DATE, today) / monthDiff(JOIN_DATE, retireDate) * 100
```

`retire_date` 는 `lib/profile.ts` 의 `calcRetireDate()` 결과다.
현재 규정은 `month_end` — 만 60세 생일이 속한 달의 말일이므로 **2034-06-30**.
과거에는 입사 기념일(2034-02-23)로 잘못 잡혀 있었다.

정년 표기는 `retireDate` 의 연·월을 그대로 쓴다 (`2034년 06월`).

## 퇴직소득세 계산 (2023년 개정)

### 계산 흐름

```
1. 퇴직급여 = 평균임금 × 30일 × 근속연수
2. 근속연수 공제액 계산
   - 5년 이하: 100만원 × 근속연수
   - 5~10년: 500만원 + 200만원 × (근속연수 - 5)
   - 10~20년: 1500만원 + 250만원 × (근속연수 - 10)
   - 20년 초과: 4000만원 + 300만원 × (근속연수 - 20)
3. 환산급여 = (퇴직급여 - 근속연수공제) ÷ 근속연수 × 12
4. 환산급여 공제
   - 800만원 이하: 전액
   - 800~7000만원: 800만원 + 초과분 × 60%
   - 7000만원 초과: 4520만원 + 초과분 × 55%
5. 과세표준 = 환산급여 - 환산급여공제
6. 산출세액 = 과세표준 × 누진세율
7. 퇴직소득세 = 산출세액 ÷ 12 × 근속연수
```

### 누진세율 구간

| 과세표준 | 세율 | 누진공제 |
|----------|------|----------|
| 1,400만원 이하 | 6% | 0 |
| ~5,000만원 | 15% | 126만원 |
| ~8,800만원 | 24% | 576만원 |
| ~1억 5천만원 | 35% | 1,544만원 |
| ~3억원 | 38% | 1,994만원 |
| ~5억원 | 40% | 2,594만원 |
| 5억원 초과 | 42% | 3,594만원 |

### 실효세율 — 두 계산 방식이 섞여 있다

`tableRows` 의 `taxMan` 은 행마다 출처가 다르다. 실효세율(`taxMan / grossMan`)을
쓸 때는 **재계산하지 말고 행의 값을 그대로** 써야 한다 (`taxRateAt()`).

| 연도 | 출처 | `taxMan` |
|------|------|----------|
| 2026~2029 | 법정 공식 추정 | `calcRetirementTax(grossMan, tenureYears)` |
| 2030~2034 | 사전 계산값 | `grossMan − netMan` |

두 방식이 달라 2034년을 `calcRetirementTax()` 로 다시 구하면 634만원(3.6%)이 나오지만,
표가 실제로 쓰는 값은 900만원(**5.1%**)이다.

**근속이 길수록 실효세율이 낮아지지 않는다.** 근속연수공제가 커지는 것보다 퇴직금이
커지는 속도가 빨라 환산급여가 높은 세율 구간으로 올라간다.

| 근속 | 세전 퇴직금 | 퇴직소득세 | 실효세율 |
|------|-------------|-----------|----------|
| 11년 (2026) | 8,279만원 | 256만원 | 3.1% |
| 14년 (2029) | 1억 1,377만원 | 368만원 | 3.2% |
| 15년 (2030) | 1억 4,800만원 | 600만원 | 4.1% |
| 18년 (2033) | 1억 6,900만원 | 900만원 | 5.3% |
| 19년 (2034, 정년) | 1억 7,600만원 | 900만원 | 5.1% |

## 퇴직금 커버드콜 운용 시뮬레이션

**IRP·ISA 는 운용 계획이 없어 다루지 않는다.** 퇴직금을 일시금으로 받아
일반 계좌에서 KODEX 200 타겟위클리커버드콜 **100%** 로 운용하는 기준이다.

```typescript
const CC_STOCK_CODE = "498400"        // KODEX 200 타겟위클리커버드콜
const CC_FALLBACK_ANNUAL_RATE = 0.17  // 분배 이력을 못 읽었을 때만
```

### 분배율

하드코딩하지 않고 **실제 지급 이력**에서 구한다 — 개인연금 화면과 같은 데이터다.

```typescript
getEtfDividendHistory(CC_STOCK_CODE)   // app/sim/actions.ts 재사용
  → 연 분배율 = 최근 12회 AVG(dist_rate) ÷ 100 × 12
```

조회 실패 시 `CC_FALLBACK_ANNUAL_RATE` 를 쓰고 분배율 배지에 `기본 추정치` 로 표시한다.

### 세금은 계산하지 않는다

커버드콜 ETF 분배금은 대부분 **파생상품 매매이익**이라 국내 주식형 ETF 기준으로 비과세다.
실제 과세 대상은 주당 과세표준액(`tax_base_amt`)뿐인데, 분배금의 **4~5%** 수준이다.
배당소득세 15.4%를 그 4~5%에만 매기므로 **실효세율이 1%에 못 미친다.**

금융소득종합과세도 마찬가지다. 연 2,000만원 기준을 과세표준액으로 따지면
연 분배금이 **약 4.8억**(평가액 약 28억)이어야 걸린다 — 이 표의 어느 행도 해당되지 않는다.

그래서 세전/세후 구분, 과세 대상 컬럼, 종합과세 배지를 모두 걷어냈다.
재투자도 분배금 전액으로 한다.

> 세금이 없다는 뜻은 아니다. 과표 비율은 회차마다 0%~16%로 흔들리고 운용사가
> 분배 재원 구성을 바꾸면 커질 수 있다. 도움말 `세금` 탭에 이 단서를 남겨 뒀다.

- 원금(수량)을 헐지 않고 분배금만 받는 구조라 수령액이 유지된다

### 시나리오 — 매입 → 재투자 → 수령

```
매입 시점       실수령 퇴직금 전액으로 커버드콜 매입
    ↓           분배금 전액 재투자 (holdMonths 개월)
63세(2037-06)   이후 분배금만 수령 (수량 고정)
```

#### 매입 시점 = 퇴직 시점

DB형(확정급여형)이라 **퇴직 전에는 회사가 적립금을 운용하므로 개인이 손댈 수 없다.**
그 전에 발생하는 분배금도 없다. 퇴직하는 그 시점에 전액 매입하는 것으로 본다.

#### 만 55세 이전 퇴직은 표에서 제외한다

만 55세 미만으로 퇴직하면 퇴직급여가 **IRP 로 의무 이전**되고 만 55세까지 인출할 수 없다.
이 화면은 IRP 를 운용하지 않는다는 전제이므로 시나리오가 성립하지 않아 **행을 만들지 않는다**
(`DB_ACCESS_AGE = 55`, `accessIdx`).

- 결과적으로 시뮬레이션 표는 **2029년 퇴직부터** 시작한다
- 위쪽 `퇴직 시점별 예상 퇴직금` 표는 2026년부터 그대로 둔다 —
  퇴직금을 받는 것 자체는 성립하고, 운용 시나리오만 성립하지 않는다
- **예외**: 상단 `현재 기준 예상 퇴직금` 카드의 `63세 월 분배금` 은 만 55세 매입 기준으로
  계산한 값을 남긴다. "지금 그만두면"을 보여주는 자리라 비워 두면 카드가 어색해진다.
  실현 가능한 시나리오가 아니라 참고값이라는 점을 도움말에 명시한다

수령 개시 나이는 개인연금과 같은 값(`PENSION_PER_PAYOUT_AGE`)을 `getPerConfig()` 로 읽는다.

```typescript
// 주가는 현재가 고정(상승률 0%) → 분배금만큼만 평가액이 늘어난다
grownValue(원금, 연분배율, 개월) = 원금 × (1 + 연분배율/12) ^ 개월

buyIdx     = 행 연도 × 12 + 정년월        // 퇴직 시점 = 매입 시점
필터        buyIdx >= accessIdx           // 만 55세 이전 퇴직 행 제외
holdMonths = payoutIdx − buyIdx           // 행마다 다르다
평가액     = grownValue(실수령 퇴직금, 연분배율, holdMonths)
연 분배금  = 평가액 × 연 분배율
```

- 퇴직 시점을 그 해 정년월로 잡으면 행 간 개월 차이가 정확히 12의 배수가 된다
- 실측(연 분배율 17.13%) 기준

| 퇴직 시점 | 투자 원금 | 매입 시점 | 재투자 | 63세 평가액 | 월 분배금 |
|---|---|---|---|---|---|
| 2029년 | 1억 1,009만원 | 2029.06 | 96개월 | 4억 2,924만원 | 613만원 |
| 2030년 | 1억 4,200만원 | 2030.06 | 84개월 | 4억 6,706만원 | 667만원 |
| 2034년 | 1억 6,700만원 | 2034.06 | 36개월 | 2억 7,818만원 | 397만원 |

**2030년 언저리에서 수령액이 가장 크게 나온다.** 퇴직금은 작아도 재투자 기간이 길어서다.
다만 2029→2030 구간은 퇴직금 계산 방식이 바뀌는 경계(추정 ↔ 사전 계산값)라
꼭짓점 위치 자체가 데이터 아티팩트일 수 있고, 포기하는 근로소득도 반영돼 있지 않다.
행 간 방향성으로만 읽어야 한다.

### `USER_PROJECTIONS` (하드코딩)

```typescript
const USER_PROJECTIONS: YearlyProjection[] = [
  { year: 2026, avgSalary: number, severanceFund: number },
  // ... 2034까지

```

각 연도별 예상 평균임금과 퇴직금을 수동 관리.

### `ComputedRetirement`

```typescript
interface ComputedRetirement {
  year: number
  grossSeverance: number    // 세전 퇴직금
  retirementTax: number     // 퇴직소득세
  netSeverance: number      // 세후 퇴직금
  holdMonths: number        // 재투자 개월 (payoutIdx − buyIdx)
  buyYm: string             // 매입 시점 'YYYY.MM' (= 퇴직 시점)

  // 아래는 모두 수령 개시(63세) 시점 기준
  valueMan: number          // 재투자 후 평가액
  monthlyDist: number       // 월 분배금
  yearlyDist: number        // 연 분배금
}
```

## 도움말

공용 컴포넌트 [components/HelpModal.tsx](../../../components/HelpModal.tsx) 를 쓴다.
사용법은 [environment.md](../../environment.md) 공용 도움말 절 참고.

| 위치 | variant | 탭 |
|------|---------|-----|
| 페이지 제목 | `page` (24px) | 계산 전제 / 퇴직소득세 / ⚠️ 한계와 주의 |
| 근속 진행 현황 | `section` (16px) | 계산 방법 |
| 현재 기준 예상 퇴직금 | `section` | 값 설명 / 읽는 법 |
| 퇴직 시점별 예상 퇴직금 | `section` | 컬럼 설명 / 읽는 법 |
| 퇴직금 커버드콜 운용 시 분배금 | `section` | 이 표가 뭔가요 / 컬럼 설명 / 세금 / ⚠️ 주의 |

### 설명은 전부 도움말 안에 둔다

화면 본문에는 **인라인 주석 블록을 두지 않는다.** 표 하단 `• …` 목록과 페이지 맨 아래
`계산 가정 및 주의사항` 카드가 있었으나, 설명이 길어져 표를 읽기 어려워지므로 전부
도움말로 옮기고 삭제했다. 본문에는 카드·표 헤더의 한 줄 요약만 남긴다.

- 페이지 도움말: 화면 전체 전제(DB형·평균임금·연봉 인상·IRP 미운용) + 퇴직소득세 산식 + 한계
- 카드 도움말: 그 카드의 값·컬럼과 읽는 요령. 중복 설명은 페이지 도움말로 넘긴다
- `세금` 탭은 계산에 넣지 않은 이유(실효세율 1% 미만, 종합과세 사실상 무관)와
  그 전제가 깨질 수 있는 조건을 설명한다
- 분배율·재투자 배수처럼 **조회 시점에 따라 달라지는 값은 본문에 그대로 넣는다**
  (`{(ccAnnualRate * 100).toFixed(1)}%` 식). 하드코딩하면 실제 화면과 어긋난다
- 각 탭은 박스 2~4개를 넘기지 않는다 — 다 읽히지 않으면 없느니만 못하다

## 주요 컴포넌트

### 근속 진행 바

- `START_DATE` ~ 정년 기준 진행률 시각화
- Tailwind `w-[{n}%]` 동적 스타일

### 퇴직금 요약 카드

- 현재 시점 기준 세전/세후/세액 3개 수치

### 연도별 퇴직금 테이블

- 2026~2034 행별: 연도 / 근속연수 / 세전 / 퇴직소득세 / 세후

### 커버드콜 분배금 시뮬 테이블

- 상단: 운용 기준 카드 (커버드콜 100% · 연 분배율) + 만 55세 제외 사유 문구
- 2단 헤더로 시간 흐름을 나눠 배치
  - `매입 후 N세까지 재투자` — 투자 원금 / 매입 시점 / 재투자 개월 / N세 평가액
  - `N세부터 매달 수령` — 월·연 분배금, 앰버 배경
- 만 55세 이전 퇴직 행은 아예 렌더링하지 않는다 (`ccRows` 단계에서 필터)

## 알려진 제약 사항

- 평균임금이 코드에 하드코딩됨 (입사일·정년은 `PROFILE_*` 환경 변수로 이전 완료)
- `USER_PROJECTIONS` 수동 관리 필요 (DB 연동 미구현)
- 퇴직금 기준이 되는 평균임금은 추정값 사용
- 주가 변동을 반영하지 않는다 — 분배율만 곱하므로 평가액 하락 시 분배금도 함께 준다
- 분배금 세금을 계산하지 않는다 — 실효세율 1% 미만이라 무시했다.
  과표 비율이나 세법이 바뀌면 다시 넣어야 한다
- 세율 개정 시 코드 직접 수정 필요
