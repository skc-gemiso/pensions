## 근속 진행 현황

### 날짜 계산

입사일·정년은 **공통 프로필 환경 변수**(`PROFILE_*`, `config/.env`)에서 읽는다 (개인연금 화면과 공유).
`getProfile()` 이 실패했을 때만 `FALLBACK_JOIN` / `FALLBACK_RETIRE` 상수를 쓴다.

```typescript
const profile = await getProfile()          // app/actions/profile.ts
const JOIN_DATE   = toDate(profile.join_date)    // 2015-02-23
const retireDate  = toDate(profile.retire_date)  // retire_rule 로 계산된 정년일

const progress = monthDiff(JOIN_DATE, today) / monthDiff(JOIN_DATE, retireDate) * 100
```

`retire_date` 는 `lib/profile.ts` 의 `calcRetireDate()` 결과다.
현재 규정은 `month_end` — 만 60세 생일이 속한 달의 말일이므로 **2034-06-30**.
과거에는 입사 기념일(2034-02-23)로 잘못 잡혀 있었다.

정년 표기는 `retireDate` 의 연·월을 그대로 쓴다 (`2034년 06월`).

## 퇴직소득세 계산 (2023년 개정)

### 계산 흐름

```
1. 퇴직급여 = 평균임금 × 30일 × 근속연수
2. 근속연수 공제액 계산
   - 5년 이하: 100만원 × 근속연수
   - 5~10년: 500만원 + 200만원 × (근속연수 - 5)
   - 10~20년: 1500만원 + 250만원 × (근속연수 - 10)
   - 20년 초과: 4000만원 + 300만원 × (근속연수 - 20)
3. 환산급여 = (퇴직급여 - 근속연수공제) ÷ 근속연수 × 12
4. 환산급여 공제
   - 800만원 이하: 전액
   - 800~7000만원: 800만원 + 초과분 × 60%
   - 7000만원 초과: 4520만원 + 초과분 × 55%
5. 과세표준 = 환산급여 - 환산급여공제
6. 산출세액 = 과세표준 × 누진세율
7. 퇴직소득세 = 산출세액 ÷ 12 × 근속연수
```

### 누진세율 구간

| 과세표준 | 세율 | 누진공제 |
|----------|------|----------|
| 1,400만원 이하 | 6% | 0 |
| ~5,000만원 | 15% | 126만원 |
| ~8,800만원 | 24% | 576만원 |
| ~1억 5천만원 | 35% | 1,544만원 |
| ~3억원 | 38% | 1,994만원 |
| ~5억원 | 40% | 2,594만원 |
| 5억원 초과 | 42% | 3,594만원 |

## 퇴직금 커버드콜 운용 시뮬레이션

**IRP·ISA 는 운용 계획이 없어 다루지 않는다.** 퇴직금을 일시금으로 받아
일반 계좌에서 KODEX 200 타겟위클리커버드콜 **100%** 로 운용하는 기준이다.

```typescript
const CC_STOCK_CODE = "498400"        // KODEX 200 타겟위클리커버드콜
const CC_FALLBACK_ANNUAL_RATE = 0.17  // 분배 이력을 못 읽었을 때만
const DIVIDEND_TAX = 0.154            // 배당소득세 14% + 지방소득세 1.4%
const FIN_INCOME_LIMIT_MAN = 2_000    // 금융소득종합과세 기준 (연 2,000만원)
const TAX_BASE_RATIO_FALLBACK = 0.05  // 분배금 대비 과세표준액 비율
```

### 분배율·과표 비율

하드코딩하지 않고 **실제 지급 이력**에서 구한다 — 개인연금 화면과 같은 데이터다.

```typescript
getEtfDividendHistory(CC_STOCK_CODE)   // app/sim/actions.ts 재사용
  최근 12회 기준
  → 연 분배율   = AVG(dist_rate) ÷ 100 × 12
  → 과표 비율   = SUM(tax_base_amt) ÷ SUM(dist_amt)
```

과표 비율은 **가중평균**(합계 대비 합계)을 쓴다. 회차별 비율이 0%~16%로 편차가 커서
단순평균은 대표성이 떨어진다. 조회 실패 시 각각 `CC_FALLBACK_ANNUAL_RATE` /
`TAX_BASE_RATIO_FALLBACK` 을 쓰고 분배율 배지에 `기본 추정치` 로 표시한다.

### 과세 기준 — 분배금 전액이 아니다

커버드콜 ETF 분배금은 대부분 **파생상품 매매이익**이라 국내 주식형 ETF 기준으로 비과세다.
실제 과세 대상은 주당 과세표준액(`tax_base_amt`)뿐이고, 분배금의 5% 안팎이다.
**세금 계산도 금융소득종합과세 판정도 이 과세표준액 기준으로 한다.**

```typescript
연 분배금(세전) = 실수령 퇴직금 × 연 분배율
연 과세 대상    = 연 분배금 × 과표 비율
연 분배금(세후) = 연 분배금 − (연 과세 대상 × 0.154)
월 분배금       = 각 연 금액 ÷ 12
```

실측(2026-08, 과표 비율 4.15%) 기준 실효세율은 **0.64%** 다. 분배금 전액에 15.4%를
매기던 이전 계산과는 2034년 정년 기준으로 연 423만원 차이가 난다.

| 항목 | 값 |
|------|-----|
| 실수령 퇴직금 | 1억 6,700만원 |
| 연 분배금(세전) | 2,861만원 |
| 연 과세 대상 | 119만원 → 종합과세 **미해당** |
| 연 분배금(세후) | 2,843만원 (세금 18만원) |

- 원금(수량)을 헐지 않고 분배금만 받는 구조라 수령액이 유지된다
- 연 과세 대상이 2,000만원을 넘는 행에만 `종합과세` 배지를 붙인다.
  과표 비율이 낮아 분배금이 커도 대상이 되기 어렵다

### 수령 개시 나이까지 재투자하는 경우

같은 표에서 **퇴직 직후 바로 쓰는 경우**와 **수령 개시 나이까지 재투자한 뒤 쓰는 경우**를
나란히 보여준다. 수령 개시 나이는 개인연금과 같은 값(`PENSION_PER_PAYOUT_AGE`)을
`getPerConfig()` 로 읽는다.

```typescript
// 주가는 현재가 고정(상승률 0%) → 세후 분배금만큼만 평가액이 늘어난다
netRatio    = 1 − 과표비율 × 0.154            // 분배금 실수령 비율 (약 99.4%)
holdMonths  = 수령개시 시점 − 퇴직 시점       // 월 단위
평가액      = 실수령 퇴직금 × (1 + 월분배율 × netRatio) ^ holdMonths
월 분배금   = 평가액 × 연 분배율 ÷ 12 에 다시 과세 적용
```

- 퇴직 시점은 각 행의 **그 해 정년월**(`retireDate.getMonth()`)로 잡는다.
  정년 행(2034년)은 실제 정년월과 같고, 조기 퇴직 행도 같은 월로 맞춰 개월 수 비교가 어긋나지 않게 한다
- 재투자는 세후 금액으로 한다 — 일반 계좌라 분배 시점에 원천징수된다
- 실측(연 분배율 17.13% · 과표 비율 4.15%) 기준

| 퇴직 시점 | 투자 원금 | 즉시 수령 월 | 재투자 | 63세 평가액 | 63세 월 수령 |
|---|---|---|---|---|---|
| 2026년 | 7,928만원 | 112만원 | 132개월 | 5억 882만원 | 722만원 |
| 2030년 | 1억 4,200만원 | 201만원 | 84개월 | 4억 6,354만원 | 657만원 |
| 2034년 | 1억 6,700만원 | 237만원 | 36개월 | 2억 7,728만원 | 393만원 |

일찍 퇴직할수록 재투자 기간이 길어 63세 수령액이 오히려 크게 나온다.
분배율이 11년간 그대로 유지된다는 가정이 그만큼 강하게 작용한 결과이므로 절대값은 참고치다.

각 연도별 예상 평균임금과 퇴직금을 수동 관리.

### `ComputedRetirement`

```typescript
interface ComputedRetirement {
  year: number
  grossSeverance: number    // 세전 퇴직금
  retirementTax: number     // 퇴직소득세
  netSeverance: number      // 세후 퇴직금
  yearlyGross: number       // 연 분배금(세전)
  monthlyGross: number      // 월 분배금(세전)
  yearlyTaxBase: number     // 연 과세 대상 (= yearlyGross × 과표 비율)
  yearlyNet: number         // 연 분배금(세후)
  monthlyNet: number        // 월 분배금(세후)
  overFinLimit: boolean     // 금융소득종합과세 대상 여부 (yearlyTaxBase 기준)

  holdMonths: number        // 퇴직 → 수령 개시까지 재투자 개월
  laterValueMan: number     // 수령 개시 시점 평가액
  laterMonthlyNet: number   // 수령 개시 후 월 분배금(세후)
  laterYearlyNet: number    // 수령 개시 후 연 분배금(세후)
  laterOverFinLimit: boolean
}
```

## 주요 컴포넌트

### 근속 진행 바

- `START_DATE` ~ 정년 기준 진행률 시각화
- Tailwind `w-[{n}%]` 동적 스타일

### 퇴직금 요약 카드

- 현재 시점 기준 세전/세후/세액 3개 수치

### 연도별 퇴직금 테이블

- 2026~2034 행별: 연도 / 근속연수 / 세전 / 퇴직소득세 / 세후

### 커버드콜 분배금 시뮬 테이블

- 상단: 운용 기준 카드 (커버드콜 100% · 연 분배율 · 과표 비율 + 실효세율)
- 2단 헤더로 두 시나리오를 나란히 배치
  - `퇴직 직후부터 수령` — 투자 원금 / 월 분배금(세전) / 연 과세 대상 / 월 분배금(세후)
  - `N세부터 수령 (그때까지 재투자)` — 재투자 개월 / 평가액 / 월·연 분배금(세후), 앰버 배경
- 연 과세 대상 2,000만원 초과 행에 `종합과세` 배지 (두 시나리오 각각 판정)

## 알려진 제약 사항

- 평균임금이 코드에 하드코딩됨 (입사일·정년은 `PROFILE_*` 환경 변수로 이전 완료)
- `USER_PROJECTIONS` 수동 관리 필요 (DB 연동 미구현)
- 퇴직금 기준이 되는 평균임금은 추정값 사용
- 주가 변동을 반영하지 않는다 — 분배율만 곱하므로 평가액 하락 시 분배금도 함께 준다
- 과표 비율은 최근 12회 가중평균이라 향후 회차에서 달라질 수 있다.
  운용사가 분배 재원 구성을 바꾸면 과세 대상이 크게 늘 수도 있다
- 금융소득종합과세는 대상 여부만 표시하고 초과 시 실효세율은 계산하지 않는다
- 다른 금융소득(예금 이자, 타 종목 배당)을 합산하지 않는다 — 실제 종합과세 판정은 합산 기준이다
- 세율 개정 시 코드 직접 수정 필요
