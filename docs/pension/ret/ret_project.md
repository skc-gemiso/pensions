# 퇴직연금 — 프로젝트 개요

## 개요

퇴직소득세(2023년 개정 기준)를 포함한 퇴직금 예상 계산과,
그 퇴직금을 커버드콜 ETF 로 운용했을 때의 분배금 시뮬레이션을 제공하는 화면.

- 경로: `/pension/ret`
- 상태: **완전 구현**
- 참고 파일: [app/pension/ret/page.tsx](../../app/pension/ret/page.tsx)

## 핵심 개념

### 퇴직소득세 계산 (2023년 개정)

- 근속 연수 공제: 근속 기간에 따라 과세표준에서 공제
- 환산 급여 방식: 퇴직금을 근속 연수로 나눠 12를 곱하는 환산 급여 계산
- 세율 구간: 환산 급여 기준 누진세율 적용
- 최종 퇴직소득세 = 환산 세액 ÷ 12 × 근속 연수

### 퇴직금 커버드콜 운용 시뮬레이션

- **IRP·ISA 는 운용 계획이 없어 다루지 않는다.** 퇴직금을 일시금으로 받아
  일반 계좌에서 운용하는 기준이다
- 포트폴리오: KODEX 200 타겟위클리커버드콜 100%
- 분배율: 하드코딩하지 않고 `t_etf_dividend` 최근 12회 평균에서 구한다 —
  개인연금(`/pension/per`) 화면과 같은 기준
- 세금: **분배금 전액이 아니라 과세표준액에만** 배당소득세 15.4% 를 매긴다.
  커버드콜 분배금은 대부분 파생상품 매매이익이라 비과세이고, 과세 대상은 분배금의 5% 안팎이다
  (실측 4.15% → 실효세율 0.64%). 금융소득종합과세 판정도 같은 기준이라 대상이 되기 어렵다
- 원금(수량)은 헐지 않고 분배금만 받는 구조
- **시나리오는 하나뿐이다** — 정년(2034.06)에 매입 → 63세(2037.06)까지 분배금 전액 재투자
  → 그 뒤부터 분배금만 수령. 주가는 현재가 고정(상승률 0%)이라 평가액은 재투자한 만큼만 늘어난다
- **DB형(확정급여형)이라 정년 전에는 ETF 를 매입할 수 없다.** 회사가 적립금을 운용하므로
  퇴직금은 정년에 손에 들어오고, 그 전에 발생하는 분배금은 없다.
  각 행의 차이는 &ldquo;그 해 퇴직했다면 퇴직금이 얼마인가&rdquo;뿐이고 매입·수령 시점은 모두 같다

> IRP 로 이전하면 퇴직소득세가 이연·감면되고 연금 수령 시 연금소득세(3.3~5.5%)만 부담하므로
> 세금 면에서 유리하다. 이 화면은 그 선택지를 쓰지 않는다는 전제이므로,
> 표의 세후 금액은 IRP 를 활용했을 때보다 보수적으로 나온다.

## 변경 이력

| 시점 | 내용 |
|------|------|
| 초기 구현 | 퇴직소득세 계산 + 연도별 퇴직금 테이블 완성 |
| 개선 | IRP 배당 시뮬레이션 테이블 추가 |
| v028 | 입사일·정년을 공통 프로필에서 조회. 정년이 입사 기념일(2034.02)로 잘못 잡혀 있던 것을 정년 규정(만 60세가 되는 달의 말일, 2034.06)으로 수정 |
| — | 공통 프로필의 저장소를 `my_profile` 테이블에서 `PROFILE_*` 환경 변수로 이전 |
| — | IRP 포트폴리오(커버드콜 70% + TDF 30%) 시뮬레이션을 **커버드콜 100%** 기준으로 교체. IRP·ISA 미운용 방침 반영, 분배율을 실제 지급 이력에서 조회하도록 변경 |
| — | 과세 기준을 분배금 전액 → **과세표준액**(분배금의 약 4~5%)으로 수정. 종합과세 판정도 같은 기준으로 변경 |
| — | 63세까지 재투자 후 수령하는 시나리오를 같은 표에 2단 헤더로 추가. DB형이라 재투자 시작은 퇴직 연도가 아니라 **정년 시점**으로 고정 |
| — | DB형은 정년 전 ETF 매입 자체가 불가능하므로 `퇴직 직후부터 수령` 시나리오를 삭제. **정년 매입 → 63세까지 재투자 → 63세부터 수령** 단일 구조로 정리 |
| — | 페이지·카드별 도움말 추가. 개인연금과 중복되던 모달 껍데기를 `components/HelpModal.tsx` 로 공용화 |
