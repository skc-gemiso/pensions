# 전기요금 관리 — 기술 명세

## DB 스키마

### `my_power_rate` — 요금표 (적용시작일 × 계절)

한전이 특정 일자에 요금을 인상하므로 **요금표를 이력으로 관리**한다.
청구 계산 시 `apply_start <= 사용기간 종료일` 인 것 중 가장 최근 행을 계절별로 하나씩 고른다.

```sql
my_power_rate (
    id            SERIAL PRIMARY KEY,
    apply_start   DATE NOT NULL,          -- 적용 시작일
    season        TEXT NOT NULL,          -- 'S'=여름(07.01~08.31), 'O'=기타계절
    tier1_limit   INT  NOT NULL,          -- 1구간 폭 (여름 300, 기타 200)
    tier2_limit   INT  NOT NULL,          -- 2구간 폭 (여름 150, 기타 200)
    base1         INT  NOT NULL,          -- 1구간 기본요금
    base2         INT  NOT NULL,
    base3         INT  NOT NULL,
    rate1         NUMERIC(8,2) NOT NULL,  -- 1구간 전력량 단가(원/kWh)
    rate2         NUMERIC(8,2) NOT NULL,
    rate3         NUMERIC(8,2) NOT NULL,
    welfare_limit INT  NOT NULL,          -- 복지할인 월 한도 (여름 20,000 / 기타 16,000)
    env_rate      NUMERIC(8,2) NOT NULL DEFAULT 9,     -- 환경요금 단가
    fuel_rate     NUMERIC(8,2) NOT NULL DEFAULT 5,     -- 연료비조정 단가
    fund_rate     NUMERIC(6,4) NOT NULL DEFAULT 2.7,   -- 전력기금률(%)
    vat_rate      NUMERIC(6,4) NOT NULL DEFAULT 10,    -- 부가세율(%)
    memo          TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (apply_start, season)
);
```

> 구간은 **폭**으로 저장한다. 여름 `300/150` → 0\~300, 301\~450, 451\~.
> 기타 `200/200` → 0\~200, 201\~400, 401\~.

### `my_power_bill` — 월별 청구

계산 결과는 저장하지 않고 **조회 때마다 요금표로 재계산**한다.
요금표가 적용시작일 이력으로 관리되므로 과거 청구서도 항상 같은 값이 나온다.

```sql
my_power_bill (
    id               SERIAL PRIMARY KEY,
    yyyymm           TEXT NOT NULL UNIQUE,      -- 요금월 'YYYY-MM'
    usage_kwh        NUMERIC(10,1) NOT NULL,    -- 사용량
    season_discount  INT  NOT NULL DEFAULT 0,   -- 하계/동계 할인. 저장은 음수(고지서 표기와 동일),
                                                -- 화면은 양수로 입력받아 저장할 때 부호를 뒤집는다
    welfare_yn       TEXT NOT NULL DEFAULT 'Y', -- 장애인 복지할인 적용 여부 (v024)
    target_kwh       NUMERIC(10,1),             -- 목표 사용량. NULL이면 안분 1구간 상한 자동
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

화면에 입력하는 값은 `yyyymm` · `usage_kwh` · `season_discount` · `welfare_yn` 4개다.
나머지는 유도값(사용기간)이거나 다른 탭에서 설정한다(`target_kwh`).

**사용기간 컬럼은 없다 (v024에서 제거).** 검침일이 항상 21일이라 요금월에서 유도한다.

```
derivePeriod('2026-07')  →  { start: '2026-06-22', end: '2026-07-21' }
```

- 검침일은 `lib/power-calc.ts` 의 `METER_DAY = 21` 상수다. 검침일이 바뀌면 여기만 고친다.
- 복지(장애인)할인 **금액**은 자동 계산이고, **적용 여부**만 `welfare_yn` 으로 받는다 (기본 `'Y'`).
  `'N'` 이면 할인 0원으로 계산한다.
- TV수신료는 분리 고지되어 관리하지 않는다.

### `my_power_daily` — 일별 사용량

```sql
my_power_daily (
    id         SERIAL PRIMARY KEY,
    yyyymm     TEXT NOT NULL,           -- 소속 요금월
    use_date   DATE NOT NULL,
    usage_kwh  NUMERIC(6,1),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (yyyymm, use_date)
);
```

## 요금 계산 (`lib/power-calc.ts`)

순수 함수라 DB·세션과 무관하다. 서버 액션과 테스트가 같은 함수를 쓴다.

### 1. 계절 일수 분해 — 하계 기간이 두 가지다

사용기간은 검침 다음날부터 검침일까지(`05.22~06.21`)를 **양끝 포함**으로 센다. 한전 고지서도 이 일수(31일)를 쓴다.

**하계 기간이 항목마다 다르다.** 한전 고지서로 확인한 사실이다.

| 대상 | 하계 기간 | 근거 |
|------|-----------|------|
| 전력량 요금 (누진 구간·단가·기본요금) | **07.01~08.31** | 2025-08 고지 `300×120 + 150×214.6 + 90×307.3 = 95,847` |
| 복지(장애인)할인 한도 | **06.01~08.31** | 중증장애인 할인 고시 — 6~8월 월 20,000원 / 9~5월 월 16,000원 |

2026-06 청구기간(05.22~06.21)에는 7~8월이 하루도 없는데 한도가 18,709.68원이었다.
5월 10일에 16,000원, **6월 21일에 20,000원**이 적용된 값이라 6월이 복지할인 하계에 든다.

```
전력량 계절: 기타 31일 + 여름  0일   (05.22~06.21)
복지 계절  : 기타 10일 + 하계 21일
```

구현은 `SUMMER_MONTHS_RATE = [7, 8]` / `SUMMER_MONTHS_WELFARE = [6, 7, 8]` 두 상수로 나눠져 있다.

한도액 자체(16,000 / 20,000)는 요금표의 `welfare_limit` 컬럼에서 계절별로 관리하므로,
금액이 바뀌면 요금표 관리 화면에서 수정하면 된다. 적용 **월**을 바꿔야 할 때만 위 상수를 손댄다.

### 2. 계절별 안분 (한전 일할계산)

각 계절 구간 `s`(일수 `d`, 총일수 `D`)마다 비율 `r = d / D` 로 **사용량·구간상한·기본요금을 모두 안분**한다.

```
사용량_s   = round(사용량 × r)     ← 정수 kWh 로 반올림
1구간상한_s = tier1_limit_s × r     ← 상한은 반올림하지 않음
2구간상한_s = tier2_limit_s × r
전력량요금_s = 누진 계산(사용량_s, 상한_s, 단가_s)
기본요금_s   = (사용량_s 가 속한 구간의 base) × r
```

**안분 사용량은 정수 kWh 로 반올림한다.** 2026-07 고지서(06.22~07.21, 288kWh)가 근거다.

```
86.4 / 201.6 을 그대로 쓰면   → 32,062원  (28원 초과)
86   / 202   로 반올림하면    → 32,034원  ✓ 고지서와 일치
```

마지막 구간은 반올림 대신 **나머지**(`사용량 − 앞 구간 합`)를 받아, 안분 합계가 항상 사용량과 같게 한다.

`전력량요금 = Σ 전력량요금_s`, `기본요금 = Σ 기본요금_s` (합산 후 원 단위 반올림)

### 3. 부가 항목

```
환경요금 = 사용량 × env_rate(9)
연료조정 = 사용량 × fuel_rate(5)
전기요금(할인전) = 기본요금 + 전력량요금 + 환경요금 + 연료조정
```

### 4. 복지(장애인)할인

한도액은 **복지 계절(6~8월) 기준** 일수로 안분한다. 전력량 요금의 안분과 별개로 계산한다.

```
할인한도액 = (기타한도 × 기타일수 + 하계한도 × 하계일수) / 총일수
할인액     = -min(전기요금(할인전), 할인한도액)   -- 원 단위 절사
```

2026-06 예 (05.22~06.21 = 31일, 복지 기타 10일 + 하계 21일, 전기요금 38,596원)

```
한도 = 16,000 × 10/31 + 20,000 × 21/31 = 5,161.29 + 13,548.39 = 18,709.68
할인 = -min(38,596, 18,709.68) = -18,709
```

### 5. 세금·기금·청구액

```
과세대상 = 전기요금(할인전) + 복지할인 + 하계동계할인
부가세   = round(과세대상 × vat_rate%)          -- 원 단위 반올림
전력기금 = floor(과세대상 × fund_rate% / 10)×10 -- 10원 절사
청구요금 = floor((과세대상 + 부가세 + 전력기금) / 10) × 10  -- 10원 절사
```

**2026-07 은 계절 경계를 걸친 달이라 일할계산·안분 반올림·복지할인 하계 판정이 모두 맞아야
고지서와 일치한다.** 이 달이 맞으면 나머지 조합도 신뢰할 수 있다.

시트 실측치와는 **2026-01 ~ 2026-07 일곱 달이 청구요금까지 일치**한다.

> 2025년 청구는 40~530원 차이가 나는데, 2025년 요금표의 1구간 기본요금(910원)이 추정값이기 때문이다.
> 실제 고지서 값을 요금표 관리 화면에 넣으면 맞춰진다.
> 2025-07~09 는 시트에 일할계산이 빠져 있어 대조 대상이 아니다.

## 목표 사용량 (일별 화면 잔여량 기준)

`target_kwh` 가 NULL 이면 **안분된 1구간 상한**을 자동 목표로 쓴다.

```
목표 = Σ (tier1_limit_s × d_s / D)
```

- 여름만 걸친 기간(07.22~08.21) → `300`
- 기타계절만 → `200`
- 경계를 걸치면 그 사이 값 (예: 기타10 + 여름21 → 200×10/31 + 300×21/31 = 267.7)

값을 직접 입력하면 그 값이 우선한다. `잔여량 = 목표 − 일별 합계`

## 서버 액션 (`app/life/power/actions.ts`)

| 함수 | 설명 |
|------|------|
| `getBills()` | 청구 목록 + 계산 결과 (최신순) |
| `getBill(yyyymm)` | 청구 1건 |
| `upsertBill(data)` | 청구 등록·수정 (`yyyymm` 기준 UPSERT) |
| `deleteBill(yyyymm)` | 청구 삭제 (일별 사용량 함께 삭제) |
| `getDailyUsage(yyyymm)` | 해당 요금월 일별 사용량 + 합계·목표·잔여량 |
| `upsertDailyUsage(yyyymm, use_date, kwh)` | 일별 사용량 1건 저장 (`kwh` null이면 삭제) |
| `getRates()` | 요금표 전체 (적용시작일 최신순) |
| `upsertRate(data)` | 요금표 등록·수정 |
| `deleteRate(id)` | 요금표 삭제 |

`getBills` / `getBill` 은 조회 시 `lib/power-calc.ts` 로 계산해 내려준다.
