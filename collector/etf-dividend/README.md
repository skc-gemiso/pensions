# ETF 분배금 수집기

`t_stock_list` 의 ETF 를 운용사 공시와 맞춰본다.

```bash
cd collector/etf-dividend
pip install -r requirements.txt
playwright install chromium

python main.py                              # 대조 리포트만 (DB 변경 없음)
python main.py --apply                      # 기존 행을 공시값으로 맞춘다
python main.py --apply --insert-months 2    # + 최근 2개월 신규 INSERT  ← 일일 수집
python main.py --apply --insert-all         # + 상장 이후 전체 INSERT (주의)
python main.py --samsung-tab 1년            # 삼성 기간 탭 (기본 상장이후)
python main.py --show-browser               # 브라우저 띄워서 확인
```

**스케줄**: GitHub Actions `.github/workflows/etf-dividend-collect.yml`
— 매일 09:00 UTC (**18:00 KST**), `--apply --insert-months 2`

## 공시를 정답으로 둔다 (2026-10 이관 완료)

수동 입력 행과 공시는 **주당분배금이 매월 일치하고 지급기준일만 3~5일 달랐다.**

| | 지급기준일 | 실지급일 | 분배율 | 주당분배금 | 과세표준액 |
|---|---|---|---|---|---|
| 공시 (498400 9월) | 2026-09-15 | 2026-09-17 | 1.4468 | 300 | 2 |
| 이관 전 DB | 2026-09-10 | 2026-09-17 | 1.42 | 300 | 0 |

`(종목코드, 연월, 주당분배금)` 으로 짝을 찾아 **20건을 공시값으로 옮겼다** (`apply.py`).
같은 달에 같은 금액이 두 번 나오는 일이 없어 이 키로 충분하다.

기준일을 바꾸면 계좌 입금 행의 비고 키(`분배금: {코드} ({기준일})`)도 바뀌므로
옛 키 행 12건을 함께 지웠다. 새 입금 행은 Cron 이 다시 만든다 (합계 6,988,727원 동일).

### 13일 기산이 이제 맞다

`getMonthlyDividendByAccount` 은 "해당 월 13일까지 누적 수량" 으로 분배금 수령 수량을 센다.
이관 전 기준일(10일)에는 기준일 **뒤** 수량을 세는 셈이라 앞뒤가 안 맞았다.
공시 기준일이 15일(월중배당)이므로 **13일 = T-2 결제일** 이라 규칙이 들어맞는다.

단 이 `13` 은 하드코딩이다. **월말배당 ETF(기준일 30일, 예: `0219E0`)에는 맞지 않는다**
— 그 종목을 보유하게 되면 `기준일 − 2영업일` 로 일반화해야 한다.

## 수집 범위 규칙

- `--apply` 는 **기존 행 수정만** 한다 (공시와 짝이 맞는 행)
- 공시에만 있는 행은 상장 이후 전체가 잡힌다 (`069500` 은 2003년부터 67건)
  → `--insert-months N` 으로 잘라 넣는다. 제한이 없으면 매일 과거를 쌓으려 한다
- 공시에서 짝을 못 찾은 DB 행은 **건드리지 않는다** (`[유지]` 로 알림)

## 운용사 매핑

종목명 앞 브랜드로 가른다 (`db.BRAND_TO_HOUSE`). 새 운용사 ETF 를 담으면 여기에 추가한다.

| 브랜드 | 운용사 | 공시 원천 |
|--------|--------|-----------|

## 운용사별 수집 상태와 한계

세 사이트 모두 표를 JS 로 그려 raw HTML 이 빈 껍데기다 → **Playwright 필수**.

### 삼성 KODEX — 동작 ✅ (엑셀)

화면 카드를 긁지 않고 **엑셀다운받기** 버튼을 눌러 받는다. 카드 목록은 기간 기본값이
1개월이고 아래쪽이 지연 로딩돼 과거를 다 못 본다. 엑셀은 선택 기간 전체가 한 파일로 온다.

- `상장이후` 탭 → **2,225행** (498400 은 21건 = DB 와 같은 건수)
- `상품코드` 열이 따로 있어 종목 매칭이 정확하다
- 과세표준액을 **준다** (없으면 `-`)
- 받은 파일은 **레거시 BIFF(.xls)** → `xlrd` 필요
- 날짜가 `YYYYMMDD` (구분자 없음) 로 온다 — `_date()` 가 이 꼴도 받는다
- 온보딩 팝업 dim 이 클릭을 먹으므로 `_KILL_OVERLAY` 로 지우고 JS click 으로 누른다

### KB RISE — 동작 ✅

- 전용 현황 페이지가 없다. 공지 게시글 본문에 표가 들어 있다
  (`종목 | 종목코드 | 좌당 예상분배금 | 좌당 과세분배금 | 분배율`)
- **표는 DOM(`<table>`)으로 읽는다.** `innerText` 를 줄 단위로 쪼개 탭으로 나누면 글마다
  렌더링이 달라 놓친다 — 어떤 글은 한 줄에 탭으로 구분되고(837), 어떤 글은 셀마다 줄이 바뀐다(835·833·829).
  그 탓에 보유 종목 `0094M0` 이 공지에 있는데도 한 건도 안 잡혔다
- 공지 목록 항목은 `href` 없는 `role=button` div → 클릭해 들어가고 `go_back` 으로 돌아온다
- **금액이 "예상분배금" 이다.** 기준일 전에 공지하고 `지급 예정 금액(변경) 안내` 가 따로 난다 — 확정치가 아니다

### 미래에셋 TIGER — 부분 동작 ⚠️ (엑셀)

**엑셀다운로드** 를 누른다. 화면 표는 20행(`listCnt` 기본값)만 읽히고, 숨은 `listCnt` 를
키워도 서버가 무시하며 연·월 `select` 에 `change` 를 발생시켜도 재조회가 걸리지 않았다
(페이징 컨트롤도 DOM 에 없다). 엑셀이 유일한 통로다.

- 받은 '.xls' 는 실제로 **HTML 표**다 (`<!DOCTYPE` 로 시작) → `xlrd` 불필요
- 과세표준액까지 준다
- **종목코드 열이 없다** → `t_stock_list` 의 종목명으로 맞춘다 (`name_to_code`)
- **한계: 엑셀도 화면에 걸린 기간만 담는다** (실측 34행) → 과거 소급 불가
- 보유 종목 `0183J0`(TIGER 미국우주테크)은 공시에 **없다**.
  테크 ETF 라 분배가 없는 것으로 보이지만, 과거를 못 봐서 단정할 수는 없다
- **GitHub Actions 러너에서는 엑셀다운로드 버튼이 안 보인다** (2026-10-03~08 매일 실패).
  로컬(한국 IP)에서는 정상이라 해외 IP 차단으로 추정한다. 실패 시 로그에 페이지 title·url 을 남긴다

## 운용사 수집 실패 처리

운용사별로 따로 수집한다. 한 곳이 실패해도 나머지는 수집·반영하고,
실패한 운용사는 `::warning::` 으로 Actions 주석에 남긴 뒤 **exit 0** 으로 끝낸다.
단 **모든 운용사가 실패하면** 반영할 것이 없으므로 `::error::` 를 남기고 DB 반영 없이 **exit 1** 로 끝낸다
(2026-10-09 수동 실행에서 러너가 세 곳 모두 막혀 녹색인데 수집 0건이었다).
실패한 운용사 종목은 공시가 비어 `keep` 으로 분류될 뿐 DB 행은 지워지지 않는다.

## 계좌 입금 연동

수집기는 `t_etf_dividend` 만 쓴다. 계좌 입금 행은 만들지 않는다.

입금 계산 규칙은 `lib/dividend-deposits.ts` 한 곳에만 두고, `/api/cron/stock-sync` 가
매일 `syncAllDividendDeposits()` 를 돌려 맞춘다. 비고 키로 지우고 다시 넣는 방식이라
매일 돌려도 중복되지 않는다. Python 쪽에 같은 계산을 복제하지 않는다.
